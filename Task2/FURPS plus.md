# Открытие депозитов через сайт
| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| **F**| **Функциональные (Functionality)**     |              |
| F1  | Клиент должен видеть актуальные предложения  по депозитам на сайте|              |
| F2  | Клиент может оставить свой номер и ФИО рядом с предложением для обратного звонка.<br>Такая заявка должна попадать в систему кол-центра |              |
| F3  | После звонка такая заявка должна попасть в АБС |              |
| F4  | Заявку на открытие депозита подтверждает менеджер бэк-офиса в АБС |              |
| F5  | После подтверждения условий и открытия депозита клиенту должна придти СМС |              |
| **U**   | **Удобство использования (Usability)**|              |
| U1    | Интерфейс сайта должен соответствовать системе дизайна для приложений, которая принята в компании |              |
| **R**   | **Надёжность (Reliability)**|              |
| R1 | Сайт должен быть доступен 24/7|              |
| **P**   | **Производительность (Performance)**   |              |
| **S**   | **Поддерживаемость (Supportability)**  |              |
| S1 | Обеспечить разработку документации|              |
| S2 | Обеспечить внутреннюю экспертизу по новым внедряемым технологиям|              |
| **+R**  | **+ Ограничения (Restrictions)**|              |
| +R1  | Трафик между сайтом и бэкендом должен шифроваться|              |
| +R2  | Для открытия депозита через сайт клиент должен лично придти в отделение для подтверждения личности| |
| +R3  | Доработка функционала работы с СМС должна выполняться внутренними ресурсами без привлечения подрядчиков|              |
| +R4  | На бэкенде сайта должен быть настроен файерволл и балансировщик нагрузки для защиты от атак |*безопасность*|


# Открытие депозитов через Интернет-банк
| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| **F**| **Функциональные (Functionality)**     |              |
| F1  | В интернет-банке клиент должен видеть свои персональные условия по депозитам|              |
| F2  | Клиент может открыть депозит прямо из интернет-банка, подтвердив решение по СМС. <br> Такая заявка на депозит должна попадать в АБС банка|              |
| F3  | Заявку на открытие депозита подтверждает менеджер бэк-офиса в АБС |              |
| F4  | После подтверждения условий и открытия депозита клиенту должна придти СМС |              |
| **U**   | **Удобство использования (Usability)**|              |
| U1    | Интерфейс интернет-банка должен соответствовать системе дизайна для приложений, которая принята в компании |              |
| **R**   | **Надёжность (Reliability)**|              |
| R1 | Сайт и интренет-банк должны быть доступны 24/7|              |
| R2 | В случае проблем в одном из ЦОД система должна быть доступна|              |
| **P**   | **Производительность (Performance)**   |              |
| P1 | Отклик по операциям не должен первышать 1 сек. |              |
| **S**   | **Поддерживаемость (Supportability)**  |              |
| S1 | Обеспечить разработку документации|              |
| S2  | Обеспечить внутреннюю экспертизу по новым внедряемым технологиям            |              |
| **+R**  | **+ Ограничения (Restrictions)**                                        |              |
| +R1  | Трафик между интернет-банком и бэкендом должен шифроваться|              |
| +R2  | Хранение персональных тсавок должно быть перенесено в АБС|              |
| +R3  | Доработка функционала работы с СМС должна выполняться внутренними ресурсами без привлечения подрядчиков|              |
| +R3  | Для базы данных интернет-банка должна быть настроена репликация в slave-базу. Все запросы справочной неоперативной информации должны быть направлены на реплику|*Снять нагрузку с OLTP базы*|
| +R4  | Бэкенд интернет-банка должен взаимодействовать с API АБС через KAFKA|              |
| +R5  | Бэкенд интернет-банка должен поддерживать горизонтальное масштабирование |              |
